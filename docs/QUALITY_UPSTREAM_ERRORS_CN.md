# 质量运维规则的上游错误处理

适用源码：插件 **0.30.9**、UI **13.7.9**，官方 CPA 8.0.76。产品决策见 [质量运维逻辑](QUALITY_OPERATIONS_LOGIC_CN.md)，源码边界见 [架构说明](QUALITY_OPERATIONS_ARCHITECTURE_CN.md)。各版本的构建、集成和本地部署结果见 [版本记录](CHANGELOG_CN.md)。

## 两条策略独立设置

在「质量运维 → 编辑规则」分别配置「答错后的处理」和「上游错误处理」。“答错仅检测，上游错误停用”是合法组合。自定义题、视觉题、人工评审题也可在实际支持的管理探测通道上处理明确上游错误，不需要标准答案。人工补充评审不会执行自动处置。

新规则默认答错仅检测、自动恢复关闭、定时关闭。在支持凭证处置的宿主上，UI 四项上游错误仍默认预选「暂停凭证」（对应普通停用 `disable_credential`）。编辑已有规则保留明确配置；旧规则未配置的项显示「不处理」。保存与预览不调用模型。

| 错误条件 | 可以触发的证据 | 不属于该条件的情况 |
| --- | --- | --- |
| 401 认证失败 | 实际定向探测收到上游 HTTP 401 | CPA 管理接口鉴权失败、目录读取失败 |
| 402 付费要求 | 实际上游 HTTP 402 | 回答中出现付款字样 |
| 429 账户额度耗尽 | 上游 429 且具有明确账户额度耗尽证据，例如 `insufficient_quota` | 普通限流、单模型限额、请求数或 token 时间窗、部署/端点/区域/项目配额、冷却 |
| 指定模型不支持 | 明确针对所选模型的上游 400/404；或已核实且非空的 CPA 模型目录缺少所选模型 | 泛化参数错误、空目录、未核实目录、目录读取失败 |

文件凭证经 CPA 的 API-call 探测时，外层管理请求须成功。回执须包含唯一的整数 `status_code`（200–599）和字符串 `body`，空字符串也是有效正文。缺少必需字段、字段重复或类型错误时，样本记录管理接口错误。上游 429 的响应头若明确显示请求数或 token 时间窗的剩余量为零，即使正文同时给出额度错误码，也只记录该次 HTTP 429。账户套餐本身存在每周重置周期仍可按实际账户额度证据判断。

对于 400/404，已知模型错误码或明确的模型不支持响应可以作为依据。错误字段或可识别的错误文案点名模型时，模型 ID 须与本轮请求逐字匹配，包括大小写。配置定向探测按实际提交给上游的映射模型匹配。

错误样本的质量判定仍为未知，不计为答错。首个命中已配置处置的明确错误可以提前结束该对象本轮剩余样本，其他对象继续执行。上游错误不要求答题整轮完成；答错停用、删除与恢复仍要求各自的完整答题证据。

规则选择 A、B，已核实目录只有 B 时，为整个对象生成缺少 A 的目录检查结果，并应用「指定模型不支持」策略。本轮不继续测试 B，也不绕过目录尝试 A。结果有目录来源、缺失模型与处置状态，没有伪造的 HTTP 响应或答题样本；不计为整轮通过或答错。供应商定向模型映射尚不能核实时，显示实际能力问题，不能将其包装成已取得的模型错误证据。

## 错误停用与 CPA 手动启用

任一规则按上游错误策略停用整个凭证或已授权供应商组后，所有规则的普通答题与恢复复检都退出该对象。开启“答题正确后恢复”不能覆盖此限制。仍有效的错误来源只用于追溯和退出检测，不创建答错恢复归属。

状态读取继续进行。插件在正常目录刷新、手动测试提交、规则派发和执行复查中读取 CPA 当前状态。管理员在 CPA 启用对象后，CPA 立即负责其业务启用；插件自动结束旧普通停用阻断和旧恢复归属，保留历史。无需人工核对、额外模型测试、删除规则、重启或等待专门轮询。

智商测试接受当前已核实且可用的供应商 `active`、`registered` 状态。已选计划遇到页面缓存中的普通停用状态时，点击“开始测试”先读取当前状态；仍停用则不提交模型任务，已经启用则正常提交。读取失败显示实际连接、目录或身份问题，不用历史停用记录代替当前 CPA 状态。

正常读取观察到启用时，会取消依赖旧处置的排队和进行中任务，并清除相关旧计数、旧证据签名。晚到的旧错误不能再次停用。下一轮按各规则当前类型、范围和定时授权重新选择；新一轮明确错误仍可再次触发当前策略。插件不修改其他规则的启用或定时设置，也不启动管理员停止的规则。

## 跨规则错误来源

A 因完整答错停用对象后，B 在「全部」范围可以保持停用进行检测。B 无权借此恢复、删除对象或接管 A 的答错恢复归属。

若 B 取得新的明确上游错误，且该错误配置为停用，插件先核实当前停用状态、条目、规则版本和本轮快照，再保存 B 的错误来源。原 A 归属、原动作与 B 的规则、运行、模型、错误证据和时间分别保留。对象已停用，因此 CPA 停用请求增量为零；随后 A、B 和其他规则均退出答题及恢复。B 配置为仅记录时，不改变 A 的恢复资格。

处置记录展示错误来源规则与原答错恢复归属。删除 A 或 B、清空检测历史都不会清除仍有效的上游错误停用来源，也不会写 CPA 启停。未知写入继续隔离，不重放。正常读取确认 CPA 已启用后，旧错误来源结束阻断。

## 供应商、协议和接口边界

文件凭证使用官方 API-call 定向探测；供应商通过官方认证配置接口读取当前配置，在后端内存中使用密钥定向探测。密钥不进入前端、日志或回答历史。停用期间始终保持停用。

只能整组启停的提供商需要本规则明确授权该组；选择 AI 提供商、选择单路由或选择全部对象均不代替授权。已授权组的一条路由提供明确上游错误时可以处理整组。未授权时保留结果与具体限制，不写入整组配置。供应商删除当前不支持。

普通文件状态/删除接口没有原子条件写入；插件的写前、写后检查无法消除最后校验与实际写入之间的外部并发窗口。供应商配置写入使用强 ETag 与 `If-Match`；冲突结束本次写入，不盲目重试。回执未知保留处置待核对。

供应商密钥或配置修改可能改变 CPA 的 AuthID/auth_index，公开接口没有可证明所有编辑连续性的持久条目 ID。插件不按名称、列表位置或配置摘要猜测恢复归属。无法唯一对应时保留旧记录并说明关联问题；另一个当前已启用对象按当前身份正常使用。具体限制见 [条目与快照](QUALITY_CREDENTIAL_ACTIONS_CN.md#条目归属与本轮快照)。

API 的 `upstream_error_actions` 键为 `unauthorized`、`payment_required`、`quota_exhausted`、`model_unsupported`，值为 `observe_only`、`disable_credential` 或允许范围内的 `delete_credential`。API 新建省略该对象表示无错误处置；编辑省略保留旧配置，显式空对象清除。UI 保存显式提交四项。

## 回归覆盖

`error_only_questions_test.go` 覆盖无标准答案的立即执行、定时执行、提前错误停用与人工评审不处置。`error_policy_disabled_test.go`、`current_state_test.go`、`manual_error_policy_test.go` 覆盖所有范围退出、CPA 启用后重新纳入、旧任务失效及连接失败。`credential_entry_lifecycle_test.go`、`provider_entry_lifecycle_test.go` 覆盖跨规则来源、原答错归属、零重复写入和组授权。浏览器脚本 `verify_upstream_actions_ui.cjs`、`verify_manual_provider_selection.cjs`、`verify_operations_live.cjs` 覆盖编辑、提交、刷新与错误原因显示。

`TestManagedUpstreamCondition` 和 `TestUnconfirmedUpstreamErrorsNeverRemoveCredential` 分别核对分类边界和处置后的实际写入次数，覆盖时窗限流、模型身份冲突与无效管理回执。`TestProviderProbeHonorsRateCounters` 通过假上游验证供应商直连时也采用该 429 判据。

隔离 CPA 集成入口为 `smoke_credential_policy.py --quality-operations`、`--error-suspensions` 与 `--manual-readmission`。测试只使用假凭证和假上游；实际执行结果见本轮交付记录。
