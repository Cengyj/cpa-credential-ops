# Credential Ops 0.32.0 后台服务、命令与数据

本页描述 0.32.0。0.32.1 源码增加了跨浏览器重开的手动测试命令引用、账号任务查询和逐成员补检，详见[后续复核](SERVICE_VERIFICATION_0_32_1_CN.md)。

适用范围为官方 CPA 8.0.76、插件 0.32.0、UI 14.0.0 和内嵌 Go/Sobek 2.2.1。对照起点是工作区提交 `d557de6` 的插件 0.31.0 和 UI 13.8.0。启动时已有的 Git 忽略配置改动、两份删除记录及两份未跟踪提示词均保留。本次新增行为和测量见[交付验收](SERVICE_VERIFICATION_0_32_CN.md)。

## 服务与界面

官方宿主先对浏览器的 `/v0/management/plugins/model-quality/` 请求鉴权，插件再分发到账号或质量服务。本文的相对路由均位于该前缀。公开 GET 只提供静态文件。浏览器用插件自己的保存身份访问 CPA，首次设置、受控迁移、显式轮换和清除使用带修订的连接命令。账号、目录和 `GET /connection` 均无权安装密钥。浏览器退出只影响本站点的页面访问。

原生注册取得质量库单实例锁，恢复规则、任务、预算、许可与协调收据，启动账号服务和质量 worker。管理连接先读私有记录，再由一个协调器异步核验回环 CPA。普通配置变更复用实例；数据目录、队列容量、worker 数或回环地址需要变化时，原生入口撤销旧实例、排空回调并关闭服务及数据库，再创建替代实例。管理 HTTP 请求从取得连接到关闭响应体均属于该实例，关闭会取消网络上下文并等待释放。原生 SDK 的同步调用受宿主能力约束。[原生入口和服务生命周期](../plugin/cmd/model-quality/lifecycle.go) · [后台连接](../plugin/quality/management_connection.go)

页面分别保存浏览器身份、当前工作区读取状态、后台连接状态、运行或命令 ID 和未提交草稿。进入账号工作区先读账号；此时仅连接状态接口 503 仍可查看和编辑账号。登录身份未验证时限制探测数量。资源更新失败时显示相应资源错误；后台状态、统计、账号目录的刷新不产生业务命令。规则与账号批次的未决引用按 ID 分别保存。关闭最后一个标签再返回，先经正式鉴权，随后按原 ID 查询。手动智商测试的临时选择按标签隔离，新标签可查服务端运行历史。页面销毁仅结束展示读取。[工作区读取](../plugin/ui/workspace.js) · [访问客户端](../plugin/ui/client.js) · [命令回执](../plugin/ui/commands.js)

| `/login/vault/status`、`/login/vault/entry`、`/login/capabilities`、`/login/targets` | 私有账号库及本地密钥材料管理已记住的登录信息，能力和可用目标从当前引擎与 SDK 取得 | 鉴权 GET 展示状态。保存及删除走显式命令，登录使用前检查条目与身份；密码、种子及令牌均不进入状态展示或批次收据 |

| `/login/conversion/preview`、`/login/conversion/upload` | 输入在内存转换，界面可下载预览。明确选择上传后，由服务依照当前许可和本轮身份调用 SDK | 批次受理后独立运行，逐项写前记录意图；保留每项结果。服务中断有在途写入时进入核对。原文、token 和旧 HTTP 回调上下文不进入批次记录 |
| `/runs` 手动测试、`/runs/detail`、cancel、review | `quality.db` 保存冻结题目、对象、模型、样本、预算、结果和幂等关联；启用 OAuth 可走 SDK，提供商核实配置后走适用路径 | POST 由当前服务端目录和策略准入，允许使用原 ID 找回收据。取消先阻止后续派发，已发出的调用取决于 SDK；人工评审与手动测试均不取得凭证处置权限 |
| `/rules`、scope-preview、timer、scheduling、pause | 质量库中的规则版本、对象范围、处置许可、逐规则定时许可和计划；保存及准入有各自的当前状态检查 | 规则创建可带幂等 ID；修改、暂停、删除按版本核对。轮换管理密钥保持规则许可和历史归属。展示快照不能授权执行 |
| `/rules/run`、后台 Tick 与补检 | 质量库中的计划、到期时刻、待恢复对象和派发收据；质量队列及 worker 执行新的证据采集 | 手动命令受理与子运行完成分开。已授权的过期周期合并补检；当前规则版本、当前对象和已受理对象共同去重。重新授权等待不会代替用户暂停 |
| OAuth 与 AI 提供商检测、停用、删除及恢复 | SDK 目录、CPA v8 管理响应、文件或整组执行快照、质量库中的归属和写前意图 | 只有完整可判定的答错证据才推进答错策略。明确上游错误使用独立策略并排除所有复检；CPA 启用后按当前状态重新准入。组写入要求显式组授权及完整成员证据。未知写入和历史独立暂停保留保护 |

## 命令契约

| 命令 | 受理与查询 |
| --- | --- |
| 创建规则 | `POST /rules` JSON 增加 `idempotency_key`。规则及创建收据同事务提交；同参数重复取得该规则，改参返回 409。删除后查询原创建收据仍可取得原规则 ID，重发原创建返回 410 |
| 规则立即执行 | `POST /rules/run` 携带 `id`、`revision`、`idempotency_key`，受理返回 202。通过 `GET /rules/commands?idempotency_key=…` 读取 accepted、running、completed、failed 或 interrupted。质量库存储故障使进行中的操作无法确认时，查询显示 `awaiting_verification`。completed 对应派发结果；模型输出通过 result 的运行或批次标识查询。省略命令键的老客户端沿用原回执 |
| 批量巡检与转换上传 | `POST /login/accounts/inspect` 或 `POST /login/conversion/upload` 带 `Idempotency-Key` 和 `Prefer: respond-async` 返回 202。通过 `GET /login/batches?id=…` 读取进度、结果、失败或 reconciliation_required。巡检和上传各有 1 个执行 worker、3 个等待位。取消命令为 `POST /login/batches/cancel`，用自己的 `Idempotency-Key` 提交 `{"id":"原批次 ID"}`。`cancelling` 表示已请求取消，`cancelled` 表示后端确认结束，已送入 SDK 的写入仍须核对。旧客户端仍可等待原同步结果 |
| 手动测试、账号登录及账号安全操作 | 沿用各自的原幂等键、任务与收据路径。查询收据和重开页面不签发新任务。未受理的错误、已受理的执行失败、写入待核对各自保留状态 |

一次超时可能落在本地提交之前或之后。先查同一 ID。对规则和账号批次，专用查询返回 `404 command_not_accepted` 表示在该次读取时找不到该命令。只有管理员再次明确提交才重投，仍使用原 ID 和原参数。其它 404、网络中断、未知结果继续保留待核对信息。遇到不同参数冲突、身份冲突或外部结果待核对时，保留原记录。[质量命令事务](../plugin/quality/rule_commands.go) · [账号批次](../plugin/login/account_batches.go)

目标目录首页返回 `snapshot`。续页携带同值，过期或被淘汰返回 `409 snapshot_expired`。普通首页共享 2 秒内的展示读取，每个实例最多保留四代、每代最长 2 分钟。`fresh=1` 发起或加入当前目录读取。观察到处置归属变化时，旧首页立即失效，仍可凭原标识读完当时的分页。正式执行和写前核实总是读取当前证据。

## 数据卷、升级和回滚

1. 停止 CPA，成套备份配置、CPA 凭证目录、动态库和整个插件数据卷。保留目录权限、bbolt 文件和同卷所有收据。备份与输入的凭证有相同的保密要求。本机安装器把私有备份放在工作区以外。
2. 将新动态库放入原插件挂载目录。保持相同 `data_dir` 和回环 CPA 地址。已有质量库及账号库继续使用既有记录，新增专用桶在首个相应命令时建立；页面切换、普通 GET 和数据库打开不会创建业务命令。
3. 启动时先恢复本地记录。质量侧中断派发终止，已提交子任务和派发收据在同一质量事务中。账号批次按索引遍历活动收据与未确认转换；可能进行过外部写入的项进入待核对。质量库中 credential-login 等待、账号控制库、CPA 保存及独立登录收据之间存在崩溃窗口，恢复依赖同条目收据核对。[跨库恢复顺序](CREDENTIAL_REAUTH_RULES_CN.md)
   转换的跨库提交收据缺失时，账号库保留原批次、转换身份和未确认记录。即使 CPA 文件消失，以新 ID 提交同一项仍会被阻止。损坏的提交收据会使恢复事务回滚并报告 `storage_unavailable`。先停服保全整卷，核对并修复原始提交收据，再启动只读核对。只有原批次引用、定位和确认结果一致才结束等待。已确认的是当时那一行写入，当前 CPA 状态需另行读取。
4. `management/connection.json` 以 0600 写入 0700 私有目录。显式更新经正式回环验证、临时文件 fsync、原子替换、目录 fsync 并回读一致后报告成功。授权失效需更新密钥。403、429、503、超时和响应结构异常保留材料；GET 状态在有退避时返回 `next_attempt_at`。检查只读挂载、剩余空间、所有者及权限后再按原 ID 查询结果。替换已发生而确认失败会返回 `connection_save_unknown`。
5. 账号库上限 256 MiB，其中 8 MiB 预留给已受理任务及维护。批次收据和规则命令指纹随卷保存。无活动或保护关联的普通账号命令终态结果到期后压缩为已消费标志。同一 ID 仍不能成为新授权。达到容量限制时先停止新受理并备份、核对活动记录。删除幂等桶或单独还原某个数据库会破坏跨库核对。
6. 旧二进制无法理解新命令收据。回退前停止新受理、查询未决操作并保留完整当前卷。若已发生新业务写入，不能用升级前的数据库覆盖新状态，或通过旧客户端重提新命令。恢复备份需要能同时核对外部 CPA 与账号状态。最可靠的回滚点是新版本尚未受理业务时的停机备份。历史版本早已清理且无 ID 关联的操作，无法从新版本反推归属或重建收据。

CPA 的文件状态和删除没有跨进程原子 CAS。提供商换密钥后公共 ID 可能变化，稳定连续性无法证实时保留历史归属。SDK 不公开运行时 token，也无法保证取消已递交的每个调用。端到端验证使用隔离宿主和合成依赖。[持久化路径](PERSISTENCE_CN.md) · [官方宿主限制](OFFICIAL_PLUGIN_CN.md)
