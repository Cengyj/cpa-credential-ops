# 质量运维规则的检测对象与范围

适用于官方 CPA 8.0.76、插件 **0.30.11** 与 UI **13.7.11**。范围、处置权限及公开接口限制见 [质量运维逻辑](QUALITY_OPERATIONS_LOGIC_CN.md) 和 [架构说明](QUALITY_OPERATIONS_ARCHITECTURE_CN.md)。

## 检测对象、范围和授权

每条规则独立勾选「OAuth 账户」「AI 提供商」，可以同时选择。新规则默认检测已启用的 OAuth 账户，答错时仅记录，定时关闭。宿主支持凭证处置时，编辑器为四项上游错误预选「暂停凭证」。OAuth 类别沿用文件凭证的兼容范围。供应商以配置来源、执行器、目标 ID 与密钥路由索引识别。同一服务的登录账户与 API 密钥可以分别选中。智商测试仍使用自己的选择和准入。

| 范围 | 每轮如何匹配 |
| --- | --- |
| 全部 | 已选类型的启用对象、管理员停用对象、本规则答错停用但恢复关闭的对象，以及他规则答错停用对象都可检测。停用对象保持停用；没有本规则恢复权限时只记录。有效上游错误停用仍退出答题。 |
| 仅已启用 | 匹配 CPA 中处于启用状态的对象。另列本规则因答错而停用、且获得自动恢复授权的目标为「恢复复检」。 |
| 指定对象 | 绑定一个账户、一条供应商密钥路由，或一个供应商配置组。组展开为各自独立的路由。目录缺失、身份或索引变更会影响准入。 |

纳入范围、能否执行、能否恢复和能否写入分别判断。他规则答错停用对象可在全部范围检测，但不能借只读检测取得恢复或删除权限。若新取得明确上游错误且当前规则配置停用，保存新错误来源、保留原答错归属、退出所有后续答题与恢复，CPA 停用写入增量为零。上游错误仅记录时不改变原恢复资格。

「授权启停的配置组」单独保存。对于整组生效的提供商，选择一把密钥、检测整个目录或指定整组都不能单独触发配置写入。管理员须明确授权该组，并配置对应的暂停或恢复动作。答错判定覆盖组内每条路由的全部计划样本；缺项、不完整、身份变化或未知答案都使本轮无法据答错启停。全部可判定且存在明确答错才可停用。整组恢复要求每份回答都正确，且写前组配置和成员集合仍匹配。移除凭证仅适用于原先支持删除的文件凭证。

规则固定到一条路由并授权其整组时，同组其他路由的采样依赖原绑定。派发后若原路由消失、索引变化或身份冲突，后续组员停止采样。写入前再次核对原绑定，已经收到的错误回答、上游 401 或已经查明的目录缺项也须通过这次核对。若规则直接指定配置组，已移出该组的路由退出采样，仍在组内的路由按原计划继续。

已停用的 OpenAI 兼容组可能没有运行时模型注册。插件根据官方配置目录核实组和路由，再按所选路由配置及模型映射定向调用。密钥只参与后端请求。无法确认身份、请求构造或路由时，批次显示原因。支持按单路由管理的类型使用 CPA 的 `excluded-models` 通配项，在停用与恢复时保留原有模型排除项。

## 旧规则升级

升级读取原全局供应商设置，为已有规则保存此前实际生效的范围、精准绑定和供应商观察权限。保留定时启停状态、旧范围对人工停用的限制、历史暂停及存量处置归属。改名或重启不新增提供商处置授权。管理员可编辑一条旧规则，明确采用新范围并选择该规则的对象和授权。

## 如何使用

1. 打开「质量运维」，在同一工作台查看概况、规则与运行记录。点击「新建规则」或规则上的「编辑」打开弹窗，依次填写名称、范围、模型、判题与计划。弹窗不分页，内容单独滚动，底部保持取消与保存。浅色、纯白和深色均跟随插件主题；提交时定位到第一个无效字段。
2. 新规则默认选中「仅已启用」、`gpt-6.2-sol`、思考强度 `high`、每模型 1 份。点击快捷项、从凭证目录选取，或粘贴 ID（空格、换行、中英文逗号和分号均可）；回车或按加号生成可移除的模型标签。直接保存时也会包含输入框里尚未点添加的 ID。重复模型只算一次。每轮保留规则所选的完整模型集合，目录缺项单独留证。
3. 在「判题设置」选择「题面与参考答案」，可就地展开固定题；随机题到执行时才生成。设定规则不显示预计探测次数，也不汇总样本。打开预览或保存规则都不会提交模型请求。规则编辑器按 CPA 当前目录显示各类型候选数量，「全部」含停用对象，「仅已启用」按 CPA 启停状态统计。实际准入、恢复复检与未执行原因见触发后的批次记录。读取目录失败时可保存动态范围。没有匹配时不创建空任务，不消耗调用额度。
4. 规则卡片显示检测范围、模型和答错时的处理方式。选择规则名称后，在「运行记录」查看对应历史，每页 20 次运行。「最近批次」可查看该轮各个对象的结果，「最近调度」可展开查看匹配与未执行原因，「处置记录」保留错误来源和原答错恢复归属，仅未知处置保留人工核对入口；已确认普通停用在 CPA 手动启用后自动同步。有记录时才显示相应入口。清除筛选可返回全部规则。
5. 新规则默认「仅手动」，可点击「立即执行」。点击卡片右上角的定时开关或在编辑器中启用定时，可让这条规则从下个周期开始检测。卡片显示下次执行时间，编辑器可调整五段 Cron，默认 `*/30 * * * *`，即服务端每小时整点和半点。
6. 「保留检测结果数」默认 **100**，可选 **1–200**，同一规则内每个凭证单独计数。一份主测样本记一条，无样本的诊断运行也记一条，对照回答随对应主测记录保留。后台先用本轮全部执行证据作出处置决定，再按最近的完成顺序裁剪历史。例如，两个模型各测 101 份、历史保留 3 份时，完整轮有 202 份，详情最终保留最近 3 份和原来的复核序号。在途任务、待核对写入、有效上游错误来源和历史独立暂停所需的证据可以超出这个窗口。普通答错停用的恢复归属单独保存。手动智商测试、审计和用量沿用各自的保留策略。[大轮次及重启回归](../plugin/quality/result_limit_test.go)

同一规则和对象的窗口优先计入规则已保存的最近完成记录，其余按完成时间与记录 ID 排序。主机时钟重复或回拨时仍能从规则打开最近记录。

列表和详情使用当轮保存的探测路径。冻结配置列出当时的判题与对照凭证 ID。准入阶段跳过的轮次显示计划思考强度。样本自身出现执行错误时，答案无法判断；整轮有错误而个别样本正常完成时，仍可查看该样本的判定。原始记录可从详情导出。

运行记录按轮显示。同一规则在两个时间点检查同一条供应商路由，会留下两条记录。准入阶段跳过也有记录，可以在「检测结果」看到未发起请求的原因。列表和详情用本轮保存的路由索引标识供应商。有记录时另列当时的供应商名称；缺少名称的旧记录仍可用路由索引对照。详情保留完整对象 ID。每轮独立保留，便于核对何时开始或停止调用模型。

固定对象缺席时，新记录会保留规则已核实的对象类型和绑定标识。固定供应商路由以路由索引核对，指定配置组以组 ID 核对。目录成功读取后找不到绑定，与目录读取失败，会留下不同原因。旧记录缺少能够确认类型的资料时，界面显示「对象」及原有 ID。导出的 JSON 保留当轮原始字段。

有些旧固定规则只保存了索引。规则仍存有原 ID、提供方和非空索引时，可在这条路由实际通过准入的同一事务中记下目录核实的来源。只打开预览或目录读取失败都不会补记。此后即使 ID、提供方和索引相同，来源由文件条目变为供应商路由或反向改变，也会阻止按原绑定调用和处置。

CPA 重启后，插件从数据卷恢复管理配置并验证回环接口。需要读取提供商目录、管理探测或写 CPA 的逾期定时检测等待后台就绪，随后按现行规则和当前目录派发。目录不可用与目录已核实但没有匹配路由分别记录。早期诊断保留原文。

「本轮处置」显示这一次实际发生的动作。已启用的路由答对时，即便规则配置了「答错暂停对象」，这一栏也显示「本轮未处置」。同一规则因答错暂停该对象后，开启自动恢复且复检整轮通过，才会显示「整轮通过，已恢复」。

「质量运维」可见且已连接时，页面约每 5 秒更新当前筛选和页码下的运行摘要、规则的下次执行时间、统计和对象目录。离开页面会暂停这些读取。定时器由 CPA 插件驱动，关闭页面后仍会到期执行。动态范围在每轮开始时重新读取 CPA 目录，新增对象只要已注册、启用且符合规则，就会在下个匹配周期被检查。整轮没有合格对象或目录读取失败时，可点规则名称，展开「最近调度」查看原因。

规则保存了定时许可，但规则暂停或实例调度尚未生效时，开关保持已设置并显示「定时未运行」。此时仍可关闭它，撤销保存的许可；之后恢复规则、开启全局调度或重启都不会重新授权。编辑时未改动开关只保留原配置，不会因保存名称等其他字段而启动规则。

删除规则后仍需核对的未知处置，在运行记录上方的「已删除规则的待核对处置」独立展示，不随规则筛选或分页消失。使用对应对象的「核对人工处理」读取 CPA 当前状态；只有已启用或已移除且身份/整组证据充分时才能结束隔离。读取失败会保留记录并禁用核对按钮，核对本身不修改 CPA。

管理员在 CPA 手动启用后，正常刷新、手动测试提交、规则派发与执行复查会同步旧普通记录，不增加确认按钮、确认模型测试或专门等待阶段。新一轮按每条规则当前范围重新选择；旧任务、旧错误和旧计数不会重放处置。对象停用不永久关闭规则，管理员主动停止的规则也不会因对象启用自动启动。

全部范围内，关闭自动恢复仍可检测答错停用对象并记录。仅已启用范围的停用例外只授予本规则持有且开启恢复的答错对象。两种范围都排除有效上游错误停用对象的答题与恢复；正常状态读取不因此停止。

同条目跨轮内容更新使用新快照，保留原答错归属；本轮内容变化阻止旧证据写回。供应商密钥更新若改变公开定位，CPA 没有持久条目 ID 可证明连续性时，不猜测转移恢复权限。旧记录保留，当前已启用的新定位按正常身份使用。详见 [条目与快照](QUALITY_CREDENTIAL_ACTIONS_CN.md#条目归属与本轮快照)。

CPA 重启会清空插件进程内的管理授权。需要管理探测或凭证处置的规则，应重新打开已鉴权的插件页一次。成功连接后可关闭页面，后续周期仍按规则执行。

## 默认模型、快捷项与思考强度

- 当前插件默认选中 `gpt-6.2-sol`，备选快捷项依次为 `gpt-6-astra`、`gpt-6.1-sol`。上游[质量运营规则表单](https://github.com/ranxi2001/sub2api/blob/a71bcd6238777630bb74f18106097689ce7a5836/frontend/src/views/admin/AccountQualityView.vue)新建题目检测时仅选 `gpt-6-astra`、`high`、1 份；[快捷项组件](https://github.com/ranxi2001/sub2api/blob/a71bcd6238777630bb74f18106097689ce7a5836/frontend/src/components/admin/operations/QualityModelShortcuts.vue)提供 `gpt-6-astra`、`gpt-6.1-sol` 和 `gpt-5.6-sol`。它们是录入预设，并不表示 CPA 已经注册这些模型。目录为空仍可建动态规则，没有匹配则不产生请求。
- 「管理快捷项」可增删本地常用模型，删除快捷项不会从规则移除已选模型。上游按管理员 ID 存储；CPA 管理接口没有管理员 ID，因此插件偏好仅按本站点、此浏览器配置文件和插件路径保存，不使用账号或管理密钥作标识，也不随规则上传。存储不可用时退回本页使用。
- 题目检测的多个模型共用一个**请求档位**：`low`、`medium`、`high`、`xhigh`、`max`，默认 `high`。新表单直接展示全部五档，可用方向键选择。规则编辑器展示当前配置，运行记录展示当轮冻结值；二者都不代表上游实际生效档位。旧规则的 `minimal` 等已下线档位或未指定值显示「沿用原设置」。只改名称不会改档；主动换为新档并保存后，不能再选回 `minimal`。规则不再提供 Temperature 或按天保留输入。老规则的温度不会因改名而丢失；使用旧保留策略时，留下空白继续沿用，明确填写条数才改为按条数保留。
- 上游题目检测允许 50 个模型、100 个样本；其单模型限制是另一种订阅状态探针，不是题目检测。插件默认每规则最多 8 个模型，可通过 `max_models` 调整。每模型样本数由管理员输入，大轮次按冻结的模型和份数逐份执行。单凭证随机题带对照时，主测与对照各执行所选份数。队列容量和每日 token 预算独立生效，每日调用次数仅用于统计。基础设施错误仍单列，只有完整判定的答题证据可以触发答错处置。

布局沿用 [质量运维工作台重构](QUALITY_WORKSPACE_13_0_CN.md) 的交互设计；该链接为历史布局说明，不证明本版状态与权限逻辑。

## 大样本任务

手动页与规则编辑器都能直接填写所需份数。大轮次仍逐份检查取消、目标状态、token 预算与存储容量，已取得的回答随执行落盘。手动与运维详情按页展开样本，可直接跳到指定份数。一次规则选择 2 个模型、每模型 101 份时会计划 202 份主测回答；设置只保留 3 条历史时，判定仍使用整轮证据，之后按窗口保留回答。对应的离线回归涵盖旧账本跨过第 200 次、重复命令、定时停用与复检恢复、整轮决策及同卷重启。[调用路径回归](../plugin/quality/call_count_workflows_test.go) · [大轮次与历史](../plugin/quality/result_limit_test.go)


## 上游与适配

核对的 sub2api 源码版本为 `production` 分支的 `a71bcd6238777630bb74f18106097689ce7a5836`。上游[账号选择器](https://github.com/ranxi2001/sub2api/blob/a71bcd6238777630bb74f18106097689ce7a5836/frontend/src/components/admin/operations/QualityAccountSelector.vue)与[中文质量运营文案](https://github.com/ranxi2001/sub2api/blob/a71bcd6238777630bb74f18106097689ce7a5836/frontend/src/i18n/locales/zh/qualityOps.ts)区分手选与「所有匹配账户（含之后新增）」；[模板服务](https://github.com/ranxi2001/sub2api/blob/a71bcd6238777630bb74f18106097689ce7a5836/backend/internal/service/quality_rule_template.go)会把规则同步到匹配账户。这里对齐的是范围语义，不照搬上游的账户、分组或处置模型。

CPA 插件只存一条动态规则，在**每次手动或定时执行时**按当时目录展开。新增或重新启用的匹配凭证从下一轮起纳入，不加入已经入队的批次。旧规则缺少 `target_scope` 时仍按原 `auth_id` 执行。编辑已有规则不提交 token 字段时保留它原来的输出限额；普通表单不再要求填写。后台统一管理并发和每日 token 预算。

### 周期与历史兼容

普通题目检测对照上游表单的 `defaults()`、五段解析器 `scheduledTestCronParser` 和 `scheduled_test_results` 按计划保留的逻辑；订阅状态探针的两分钟默认值不适用于本页。五段依次为分、时、日、月、星期。例如 `0 9 * * *` 为服务端每天 09:00。本机 8317 使用 `Asia/Shanghai`；其它安装读取各自服务端时区，不跟随浏览器。下次运行以 UTC 保存，列表使用该次运行在计划时区的实际偏移（含夏令时）。

旧固定间隔或带显式时区的 Cron 默认只显示原计划。勾选「改用服务端 Cron」再保存才转换，取消编辑不改变计划，仅改名称不会推迟下次运行。管理 API 新建时省略 `cron`、`max_results` 分别使用 `*/30 * * * *`、100。显式空值或非法 Cron 会收到校验错误。更新时省略计划或条数会保留原值。新规则使用 `cron` 与条数或手动保留模式，旧规则的 `interval_seconds`、`timezone`、`retention_days` 在转换前继续生效。

## 准入与保护

- 已有客户端的实例级定时授权仍适用于旧计划。新表单只写本条规则的授权，不开启实例级许可。管理员通过原定时接口明确全部停止时，也会撤销逐条授权。随后启动一条规则不会补跑未执行的旧周期或唤醒其他规则。

- 文件凭证通过 `host.auth.list`、`host.auth.models` 与 `host.auth.get_runtime` 核对身份。提供商额外核对认证接口 `GET /v8/management/config/api-keys` 的来源、索引、提供方、启停机制和模型。
- 子任务固定到具体凭证和模型，每次采样前复核选中的对象、索引与执行状态。公开接口没有与实际调用原子绑定的状态快照；最终路由仍由 CPA 决定。
- 一个批次只占一个队列位置。将使待完成范围子任务超过 1,024 个，或已无队列空间时，本轮可执行对象全部记为「队列容量不足，本轮未入队」，返回包含未执行明细的批次回执，不只运行前若干个；接口或存储故障则返回相应错误。同一规则有排队或运行中的任务时不会再开一轮。被中断的任务重启后记为中断，不重放。
- 官方宿主没有独立质量暂停、释放或可信最终证据接口。仅在答错和上游错误策略均为观察时，检测结果不会改变凭证；普通停用使用明确授权的官方管理接口，不模拟历史独立质量暂停。

## 定向探测参数

「思考强度」提供五个显式档位。旧规则原本未指定时，编辑界面可沿用原设置。无法核实定向探测的协议与思考参数组合时，预览与执行都会说明原因。

## 验证入口

- `plugin/quality/rule_objects_test.go` 对照预览、手动和定时批次，并覆盖旧规则迁移、重启、部分目录读取和单条规则修改。
- `plugin/quality/provider_adapter_test.go` 与 `plugin/quality/provider_disposition_test.go` 检查配置索引、停用快照、条件写入、受影响路由及整轮判定。`scripts/verify_rule_objects_ui.cjs` 使用真实编辑器提交合成规则。
- `scripts/smoke_provider_targets.py` 通过 `scripts/smoke_ui_package.py --provider-targets` 在隔离 CPA 上核对双密钥整组、公共模型目录、原生业务路由、上游收到的请求、条件写入和重启。`scripts/smoke_provider_route.py` 单独验证按密钥使用通配排除项的机制。
- `scripts/smoke_credential_policy.py` 和 `scripts/smoke_error_suspensions.py` 使用合成 OAuth 凭证验证人工停用检测、答错停用和恢复、上游错误退场，以及写入回执不确定时的保护。
