# 同一 CPA 条目重新授权与检测规则

适用于完整原生插件。账号巡检、手动重新授权、显式候选提交以及获准的自动重登使用账号服务。登录引擎在插件进程中运行，账号服务通过公开 SDK 核对身份和保存凭证。管理页面负责提交、查询任务和显示规则状态。账号巡检和质量规则分别由自己的后台调度器驱动。

## 写入前后

1. 账号服务把任务 ID 作为本次写入的标识。准备写入时，质量服务按 CPA 凭证 ID 持久记录等待，清理直接依赖规则的连续失败证据，取消涉及旧授权的排队或执行轮次。主体、对照、判题共用这项互斥，凭证仍有工作协程占用时，保存方等待该协程退出。
2. 更新窗口内，固定规则保留下一次执行时间。动态检测只对受影响的成员标示等待。目录读取跨越凭证更新时，该次读取的旧数据不能用于新轮次。规则的用户启用意图、逐条定时许可和全局定时设置独立保存。管理员可以继续修改、暂停、关闭定时或删除规则。
3. 账号服务在保存前复核原条目的 ID、索引、文件名、账号与工作区身份和原策略，并持久化待确认收据。自动重登还会复核全局与账号许可、当前故障证据及人工停用状态。SDK 保存完成后，插件比对物理文件、运行记录、启停状态及目标身份，然后持久化确认收据。
4. 同一条目核实成功后，只结束匹配此次提交的本地等待。下一轮按当前规则版本、定时许可、对象目录和新凭证快照执行。等待期间暂停的规则继续暂停，已删除规则保持删除。成功回调本身产生的模型请求为零。窗口前的样本保留在历史中。
5. 新建文件恰好占用已消失条目的旧位置时，之前直接指向旧位置且未经修改的规则会停止，审计记录要求核对绑定后显式恢复。替换到另一个 CPA 条目时，原绑定无法取得同一条目的成功收据。已确认的普通停用来源可通过当前 SDK 文件与运行状态对账；记录仍处于未确认写入或历史独立质量暂停时继续隔离。

## 重启与故障

| 情形 | 后台行为 |
| --- | --- |
| 准备前的登录或身份核验失败 | 任务记录具体失败阶段，旧凭证未进入写入窗口 |
| 已准备，确定在 SDK 保存前终止 | 显示“等待重新授权成功”。后续新的合规授权可以重新准备 |
| SDK 保存结果未知，或保存后运行时采用未经确认 | 保留“凭证写入待核对”，检测与下一次覆盖写入都受保护 |
| 重启后发现已受理写入的收据缺失 | 与原任务保持相同的未确认保护，保留等待，禁止覆盖 |
| 本地收据显示成功，质量服务尚未记录结束 | 重启后再次核实当前 CPA 条目和运行身份，消费同一份成功收据 |
| 启动时当前条目读取暂不可用 | 保留等待，由后台重试只读核对。账号绑定读取暂时失败时保留已确认任务，间隔 15 秒后再读取 |
| 当前账号、文件或索引与成功收据冲突 | 标示身份冲突，保留隔离 |
| 旧版本已停止的规则 | 历史准备记录缺少可关联的成功收据及用户原始意图，沿用现存规则设置 |

等待记录位于插件数据目录的 `quality.db`，使用 `meta` 桶的 `credential-login:` 键前缀。记录包含凭证定位、准备 ID、预期身份摘要和协调状态。提交收据在同一数据卷的 `accounts/login-receipts.db`，账号与任务仍由账号库管理。容器恢复应同时保全这几份数据库。恢复流程只读取已有收据及公开 SDK 目录。已受理的旧登录、模型调用和安全操作都不会被提交第二次。

官方 `host.auth.save` 没有跨进程条件写入。提交前后核对和插件进程内互斥不能消除其他管理方并发修改的窗口。SDK 的运行记录不公开实际运行时 token，确认涵盖已保存的文件材料及公开可见的运行身份和状态。

## 隔离回归

从 `plugin/` 运行以下用例，使用临时 bbolt 数据库、假账号、假 CPA、假模型上游。

```sh
go test -race ./quality -run 'CredentialLogin|CredentialRewrite|LoginClearsOnly|NewEntryAtOldLocator' -count=1 -v
go test -race ./login -run 'AccountReauthorizationCoordinatesCurrentRules|AccountBindingRechecksAfterTransientSDKRead' -count=1 -v
```

| 场景 | 观测 |
| --- | --- |
| 手动重新登录、已授权自动重登、成功收据落盘后重启 | 每个场景均为首次上传 1 次、重新授权保存 1 次、重新授权等待解除 1 次，恢复收据额外保存 0 次 |
| 更新前已有排队轮次，多条规则同时有不同状态 | 旧轮次取消 1 次，成功回调触发模型 0 次，下一次新轮次以新快照完成 2 个模型的检测 |
| 未知、未采用、失败、身份冲突的收据经两次装载 | 已终结的收据不会重新进入后台请求队列，自行提交的模型及凭证写入均为 0 |
| 账号保存已确认、读取绑定时 SDK 临时失败 | 连续 4 次界面读取合并在同一等待窗口，SDK 失败读取 1 次；下一次到期读取完成绑定，SDK 保存总数为 1 |
