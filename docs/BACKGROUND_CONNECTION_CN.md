# Credential Ops 后台连接与恢复

后台授权方案自官方 CPA 8.0.76、插件 0.31.0 和 UI 13.8.0 起提供。0.32.0 增加下次探测时间、传输关闭协调和工作区独立读取。[当前服务说明](SERVICE_LIFECYCLE_0_32_CN.md)

首次在插件中输入 CPA 管理密钥并成功保存后，容器重启只需挂回原插件数据卷。账号巡检、质量检测和后台授权各自有生命周期。

## 三条调用链

| 入口及用途 | 权限与依赖 | 中断时的行为 |
| --- | --- | --- |
| 浏览器打开插件、读取账号/目录/规则/任务、提交操作 | 静态资源位于公共资源前缀。业务请求携带当前浏览器的管理身份，由 CPA 鉴权后进入 `/v0/management/plugins/model-quality/` | 页面隐藏时减少展示轮询。重新进入同步当前数据和任务回执。网络失败保留已读数据与浏览器身份 |
| 插件后台读取 CPA 管理配置、执行受控管理探测、核实及写回状态 | 专用回环客户端，只接受回环 IP，走正式 `/v8/management/`，禁用代理和重定向。每个插件实例共用一个 HTTP 传输和一个健康检查任务 | 管理依赖进入等待，按退避探测就绪。浏览器退出不会终止后台客户端 |
| 插件执行公共 SDK、登录引擎与定向探测 | 登录服务、质量 worker、各自的操作记录和本轮身份快照 | 受理后的任务使用服务上下文。页面请求结束后可继续执行。插件真正退出时按已持久化的任务状态处理 |

## 功能依赖

| 功能 | 执行链与前置条件 |
| --- | --- |
| 账号导入、资料/代理编辑、套餐排除 | 插件账号库。访问这些管理入口仍需浏览器通过 CPA 鉴权 |
| 2FA 登录、手动重登、巡检与自动重登 | 账号调度器读取持久化全局/账号许可，使用公开 SDK 核实 CPA 条目。实际登录使用内嵌 Go/Sobek；保存前重查许可、身份和状态，通过 SDK 保存并核实，留存收据 |
| 重置 2FA、退出所有设备、可选后续授权 | 现有显式操作任务。已确认的新种子先保存，未知的远端变更保持隔离。本地完成只处理已确认的材料 |
| 凭证转换、预览、下载及上传 | 本地转换、页面下载与明确选择的 SDK 上传分开。上传使用账号库中的策略、目标核对及提交收据 |
| 普通已启用 OAuth 的原生手动测试与只观察规则 | SDK 读取身份、运行状态和模型，固定凭证执行。目录中的可选能力补充读取失败时，独立 SDK 路径可继续 |
| 文件凭证的管理探测和普通启停、删除、答错恢复 | SDK 读取并核实当前文件/运行快照；回环请求使用正式 api-call 或状态/单文件接口。停用期间可按既有许可定向探测 |
| 提供商原生模型调用 | 先通过管理配置核实路由身份，再走 SDK 固定路由；管理目录暂不可用时等待 |
| 提供商定向探测、整组处置和恢复 | 通过管理接口读取并核实组、路由与配置。上游调用使用该路由自己的凭据和代理；写配置沿用已有条件请求、整组授权和全量证据要求 |
| 即时派发、定时派发、批次、历史、日志、统计与清理 | 质量引擎管理规则、回执、预算和本地历史。每轮使用所选对象的实际路径。查看记录或清理历史不会建立后台管理授权 |

## 后台状态和操作

在上述插件管理前缀下使用以下接口。每个请求都经过 CPA 官方鉴权。

| 操作 | 请求与回执 |
| --- | --- |
| `GET /connection` | 返回 `state`、`configured`、`can_migrate`、`revision`，以及可用时的 `source`、`code` 和 `next_attempt_at`。只读取后台状态 |
| `PUT /connection` | 提交 `{"revision":当前值,"mode":"configure"}`。候选密钥取自该请求的鉴权头。使用回环只读接口验证成功并完成持久化后，才切换当前配置 |
| 旧浏览器迁移 | 使用同一个 PUT，模式为 `migrate`。仅初次无配置状态允许。明确清除后的标记跨重启保留，旧页面无权重新迁移 |
| `DELETE /connection` | 提交 `{"revision":当前值}`。以无密钥标记替换配置，后续依赖回环的工作等待。账号巡检许可和逐规则开关独立保存 |

修订号是 JavaScript 安全整数，仅比较是否相等。更新竞争或修订过期返回 409。当前浏览器退出只清除页面访问身份。同源插件保存的旧浏览器身份可用于首次迁移，后台不会把保存的密钥发给新浏览器。拒绝使用本地存储的浏览器需要在新页面重新取得自己的访问身份。

| 状态 | 含义和后续动作 |
| --- | --- |
| `unconfigured` | 当前没有可用配置。首次允许迁移；显式清除后需主动保存 |
| `waiting` | 已取得授权材料，正在等待回环服务、验证响应或恢复网络 |
| `ready` | 最近的正式鉴权和响应结构检查通过，可用于后台调用 |
| `restricted` / `rate_limited` | CPA 返回 403 或 429。保留配置，遵循 Retry-After 和可识别的 IP 封禁期限 |
| `invalid` | 当前修订的管理密钥收到 CPA 401。停止使用它，替换为不含密钥的失效标记，等待更新 |
| `error` | 私有存储、记录版本、权限、回环地址或部署配置需要核对。状态只提供诊断代码 |
| `closing` | 实例正在退出，拒绝新的回环工作并取消健康检查 |

0.32.1 源码中，当前密钥收到管理接口 401 后，如果失效标记暂时无法写入，`state=invalid`、`code=connection_invalidation_save_failed`。此时后台已丢弃内存密钥，`next_attempt_at` 是下次保存无密钥标记的时间。恢复磁盘空间或写权限后，同一协调器用原失效修订补写标记。管理员先行配置新密钥或清除授权会终止旧修订的补写。永久存储故障期间若进程退出，卷中可能仍是上次成功保存的记录；重启会先进行只读鉴权，只有通过后才会开放后台管理调用。

就绪探针使用 `GET /v8/management/observability/requests/in-flight`，读取本地计数并核实响应。初始化期间只加载磁盘状态，网络验证异步执行。单次验证限时 4 秒，临时故障从约 1 秒起指数退避并加入抖动，基础间隔上限 64 秒；CPA 指定的等待时间优先。健康时约每 90–120 秒核实一次。普通状态读取复用验证结果。管理密钥轮换不改变 CPA 凭证条目标识。

0.32.2 在同一修订上合并健康探针与业务请求同时收到的限制。403 优先显示为 `restricted`，已有 429 遇到临时 503 时保留 `rate_limited`，重试采用已知的最晚期限。业务请求收到官方临时 IP 封禁说明时，`code=management_temporarily_banned`。管理员可查看 `next_attempt_at`，协调器到时自动核验。已有退避期间迟到的成功响应不能提前放行。[并发限制与恢复用例](../plugin/quality/management_connection_test.go) · [业务封禁与期限实测](../artifacts/verification-commercial-rounds/outer-denial-race.log)

若调用方取消时已收到**当前修订的 CPA 管理 HTTP 401**，后台仍停用该修订的密钥，需要管理员更新。仅在本地取消且未收到拒绝响应时，授权状态保留。管理 `api-call` 成功响应内的模型 401，以及该接口表示上游传输失败的外层 502，由样本路径处理。查询时先看请求所属接口、外层状态及后台状态代码。[取消与拒绝的回归](../plugin/quality/management_response_test.go) · [回环传输](../plugin/quality/management_client.go)

## 故障、调度与回执

- 页面到 CPA 的网络异常只影响当前展示。浏览器端的 401 要求重新鉴权。后台候选密钥不通过回环验证时返回插件错误 `management_key_invalid`（422），后台限流、临时不可达和权限受限各有代码。配置保存失败返回 507；原子更名后无法确认目录同步时报告 `connection_save_unknown`，停止使用不确定配置。
- 上游状态位于 api-call 的成功管理响应内部，样本记录上游错误与答题判定。上游 401、连接波动以及内容不完整分别使用各自的准入和证据规则。一次 503 或超时没有可判错的回答。已发出的模型请求及账号、启停、删除操作按原收据处理。
- 质量定时器使用服务器本地时区的五段 Cron，旧间隔计划保留。持久的到期时间与受理记录共同决定是否补检。逾期多个周期合并为一个新轮次。派发前重新检查逐规则许可、版本、当前目录和已有轮次，成功受理后回到原周期。混合范围的 SDK 分支可独立执行，待恢复对象按已受理记录去重。
- 普通预算、保留期和规则调度配置热更新继续使用现有服务；改变数据目录、worker 数、队列容量或回环地址会替换实例。退出时取消并等待旧 worker、登录服务与恢复协调任务，再打开新实例。连接材料与质量配置摘要独立。旧库只有配置摘要时，保留已保存的有效设置与逐规则许可，建立用于以后逐字段合并的宿主输入基线。
- 账号写入前，以目标条目和提交 ID 建立持久等待，清理旧证据、取消依赖旧凭证的工作并等待在途使用退出。收到匹配条目和身份的成功收据后解除本次等待。规则后续只按当下的启用意图、许可和新快照准入。中断后只读核实收据，未知写入保留隔离。管理员已在 CPA 启用的普通停用条目按当前 SDK 快照同步。
- 官方 CPA 的文件状态和单文件删除接口没有跨进程原子条件写入。插件在写前、写后分别核实条目并记录结果；无法确认时保留待核对状态。历史独立质量暂停仍受原保护。配置恢复、页面重新访问和重启均不签发真实账号安全操作或重发未知动作。

持久目录、部署 Secret 优先级和备份要求见[持久化说明](PERSISTENCE_CN.md)。详细准入与处置语义见[质量运维逻辑](QUALITY_OPERATIONS_LOGIC_CN.md)。容器重建、补检、重新授权和本机部署结果见[验收报告](BACKGROUND_CONNECTION_VERIFICATION_CN.md)。

首次保存或清除若返回 `507 connection_save_failed`，先恢复私有目录的写权限或磁盘空间，再读 `/connection` 核对原修订，按当前意图明确提交。若返回 `500 connection_save_unknown`，原子更名后的持久化结果尚待核对，后台已停用内存中的配置。修复存储后通过当前修订明确保存或清除。若连 `/connection` 和 `/rules` 都返回普通路由 404，先查询 CPA 的插件登记及注册错误，再按完整卷恢复流程处理。[只读挂载与容量耗尽实测](../artifacts/verification-commercial-rounds/final/connection-storage.json) · [质量库冷备恢复](PERSISTENCE_CN.md)

## 浏览器验收与历史脚本

UI 14.0.2 在账号工作区或其 iframe 隐藏后停止新增详情、候选和日志轮询。管理员已明确开始的日志导出可以继续读取剩余游标页。返回后同步原任务与选中记录。三个隐藏场景中的展示轮询、新增业务写入均为零，导出场景另读取了一页已经请求导出的数据。[隐藏、返回和导出实测](../artifacts/verification-commercial-rounds/ui-hidden/account-navigation.json)

在仓库根目录执行以下命令。Chromium 脚本会在回环随机端口启动合成管理服务，测试账号来自内存夹具。页面请求数量按实际到达的接口计数，包含初始化和人为触发的刷新。

```sh
node --test scripts/tests/*.test.cjs
UI_OUTPUT=artifacts/connection-ui-0.31.0 node scripts/verify_account_startup.cjs
node scripts/verify_run_receipts.cjs
node scripts/verify_operations_live.cjs
node scripts/verify_quality_concurrency.cjs
node scripts/verify_account_dialogs.cjs artifacts/connection-ui-0.31.0/dialogs
node scripts/verify_account_health.cjs artifacts/connection-ui-0.31.0/health
UI_OUTPUT=artifacts/connection-ui-0.31.0/security node scripts/verify_security_submit.cjs
UI_OUTPUT=artifacts/connection-ui-0.31.0/convert node scripts/verify_conversion_ui.cjs
```

UI 13.8.0 通过 46 个 Node 单测和 33 个浏览器连接、页面恢复与导航场景。每个导航场景的请求数和断言结果在 [本次浏览器记录](../artifacts/connection-ui-0.31.0/account-navigation.json) 中。

| 隔离场景 | 实测 |
| --- | --- |
| 已有浏览器密钥，首次迁移后两次离开并返回 CPA 侧栏，清除后台配置后再重载一次 | 4 次 iframe 加载共读取账号列表 4 次，包含打开配置对话框在内共 5 次 GET 连接状态，迁移 PUT 和清除 DELETE 各 1 次 |
| 后台初次配置或已确认失效 | 各输入 1 次有效密钥并提交 1 次配置，重新加载与退出没有配置写入 |
| 浏览器已获准迁移，后台在保存前明确返回一次 503 | 跨 iframe 重建后使用同一 revision 验证，2 次提交中 1 次配置成功，之后没有再次提交 |
| 配置已写入但浏览器丢失回执，或持久化明确失败 | 两种场景各提交 1 次，重载只读状态和当前工作区 |
| 两个标签同时编辑，清除后另一标签持有旧 revision，换密钥后迟到旧 401 | 1 次旧版本写入被拒绝，2 次明确配置变更生效，旧响应没有清除新密钥 |
| 页面临时 503 后恢复，再隐藏 65 秒 | 账号和草稿保留，隐藏期间 0 次展示读取，0 次业务写入 |
