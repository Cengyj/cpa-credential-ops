# 0.30.1 三轮商用交付审查

日期：2026-11-21（Asia/Shanghai）。本轮基于已部署的插件 0.30.0 继续审查，保留已有工作区修改，交付版本为插件 0.30.1、UI 13.7.1、内嵌 Go/Sobek 2.2.1。官方 CPA 8.0.76 源码保持不变。

## 审查方式

第一轮按凭证身份、任务生命周期、响应证据及前端并发四条路径审查，并以失败回归证明问题。第二轮检查修复的反向场景：已知未写入与未知写入、合法恢复与越权恢复、旧任务与新许可、正常协议与歧义协议、明确保存失败与回执丢失。第三轮独立复审关键改动，再执行模块、竞态、原生隔离集成、构建和安装保全检查。

所有新增验证使用假凭证、假上游、临时数据库或隔离容器。页面交互使用合成数据；不对真实账户执行模型调用、登录、测试性启停或安全操作。没有推送、GitHub 发布或额外平台构建。

## 已复现并修复的问题

| 问题 | 修复与观察到的行为 | 主要实现 |
| --- | --- | --- |
| 歧义 JSON 被视为完整答案，可触发停用、删除或恢复 | Chat、Responses、Claude、Gemini、Interactions 拒绝重复字段；三个实际假 CPA 写入反例从会写入变为零写入、未知判定 | `collector.go`、`management_client.go`、`provider_probe.go`、`commercial_evidence_test.go` |
| 流的终止边界不一致 | 拒绝 `[DONE]` 后的 Responses 完成事件；拒绝同一 Chat 流切换响应模型；正常最终响应继续通过 | 同上 |
| 人工核对在目录暂时缺项或残留启用状态时清除保护 | 文件需当前启用快照或精确删除证据；供应商组需完整、已核实的当前成员。无关供应商目录故障不阻止文件核对 | `credential_policy.go`、`provider_disposition.go` |
| 最后本地复查失败、尚未发出写入，却永久进入未知状态 | 使用明确的本地前置条件失败类型，记录本轮内容变化并保留原答错归属；后续完整新轮可使用当前内容。真正写后失败仍隔离、不重放 | `management_client.go`、`credential_policy.go` |
| 定时关闭再开启让旧队列或旧扫描继续运行 | 撤销定时许可与取消旧任务同事务持久化；扫描期间的许可变化也必须在落队列前复查。手动测试、立即执行及新许可的新轮不受影响 | `transitions.go`、`scope.go`、`scheduler.go`、`engine.go` |
| 提交请求在最终读取期间取消，仍创建任务和回执 | 在持久准入前再次检查请求取消；取消无队列、无模型调用、不消耗回执，用户可显式重新提交 | `admission.go` |
| 单对象恢复规则停止后无法显式恢复 | 使用与派发相同的原答错归属和当前快照准入；恢复规则本身零模型调用、零 CPA 启用，后续新完整轮才可恢复对象；他规则归属、未知写入、历史独立暂停仍阻止 | `rules.go` |
| 保存规则时轮询重新启用控件、丢弃用户后改的内容 | 保存期间保持字段锁定，轮询不能改写草稿；保存完成后按当前能力恢复控件 | `plugin/ui/app.js` |
| 新建规则回执丢失后重复 POST，可能创建重复定时规则 | 网络异常、408/5xx、损坏或缺少 ID/版本的成功回执均保留草稿并阻止重复新建。空列表或读取失败不证明创建失败；明确 400/409 可纠正重试，编辑仍由版本检查防重 | 同上 |
| 并发目录刷新丢弃旧响应后，提交继续使用更旧缓存 | 提交等待被替代的最新读取；最新失败或仍停用为零 POST；切连接废弃旧提交 | 同上 |
| 历史供应商再次测试丢失原索引绑定 | 保留历史绑定用于刷新后的再次核对，索引变化时零 POST；新手动测试仍按当前选择，发送体保持净化 | 同上 |

自动处置仍仅由当前规则、当前授权与本轮明确证据触发；手动评审不触发写入。供应商组授权、完整恢复、历史独立暂停、未知写入不重放等既有边界保持。

规则草稿只保留在当前页面编辑会话中；关闭、刷新或切换连接不提供持久草稿恢复。本轮未新增后端规则创建幂等，创建结果未知时需要核对现有规则，不能把页面刷新当作重试授权。
